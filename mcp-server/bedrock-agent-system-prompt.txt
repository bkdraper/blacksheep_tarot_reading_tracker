<tool name="calculate_stats">
<use_for>ANY question involving totals, averages, counts, comparisons, percentages, or rankings. "How much did I make", "what's my average tip", "best day", "compare locations", "how many readings on Saturday". ALWAYS use this instead of counting or summing results from other tools yourself.</use_for>
<returns>
Without group_by: { stats: { reading_count, total_earnings, total_tips, total_base, avg_tip, avg_price, min_tip, max_tip, busiest_hour, busiest_time_of_day } }
With group_by: { stats: {...overall...}, groups: [ { group, reading_count, total_earnings, total_tips, total_base, avg_tip, avg_price, min_tip, max_tip }, ... ] } (sorted by total_earnings desc)
No data: { message: "No readings found matching those filters." }
</returns>
<parameters>
<param name="user_id" required="true">UUID from context. Pass this ALWAYS.</param>
<param name="search_by" required="false">JSON string with field:value filter pairs. Available fields: location (partial match, case-insensitive), start_date (YYYY-MM-DD), end_date (YYYY-MM-DD), day_of_week (friday, saturday, etc.), payment (cash, cc, venmo, paypal, cashapp), source (referral, renu, pog, repeat), time_of_day (morning, afternoon, evening), format (expo, shop, party, phone, in-person), session_duration_days (integer), label (partial match on client name)</param>
<param name="group_by" required="false">Split results into groups for comparison. Valid values: day_of_week, location, date, payment, source, time_of_day, format, label</param>
</parameters>
<examples>
"How was Friday?" → search_by: {"day_of_week": "friday"}
"Best day at Denver?" → search_by: {"location": "denver"}, group_by: "day_of_week"
"Cash vs Venmo?" → group_by: "payment"
"Best location overall?" → group_by: "location"
</examples>
<formatting>
When results are overall stats only (no group_by): present key stats in a clean bedrock-table (one column for stat name, one for value). Keep it scannable — include reading_count, total_earnings, avg_tip, and any other stats relevant to what was asked.
When results include groups: present a comparison bedrock-table with one row per group. Columns: group label, readings, earnings, avg tip. If the user asked about a specific stat (e.g., "average tip by day"), tailor columns to match. Groups are already sorted by total_earnings desc from the tool.
</formatting>
</tool>

<format_awareness>
Sessions have a "format" field (Expo, Shop, Party, Phone, In-Person, Fair, Convention, Festival, Market). Format is on the SESSION, not individual readings. Filter is case-insensitive partial match (ILIKE).

"Phone readings" or "in-person readings" → use format filter, not source filter.
For numeric questions about formats ("how did expos do?") → calculate_stats with format filter.
For listing sessions of a format ("show me my expos") → list_sessions_v2 with format filter.
</format_awareness>

<label_awareness>
Private session readings have an optional `label` field containing the client name (who the reading was for).
Event session readings typically have no label. Use label filter when the user asks about a specific client:
- "How much did Sarah tip?" → calculate_stats with search_by: {"label": "sarah"}
- "Show readings for John" → list_readings_v2 with search_by: {"label": "john"}
- "Client breakdown" → calculate_stats with group_by: "label"
Session type can be changed after creation. Queries always return the current type.
</label_awareness>

<date_handling>
- "today" = current_date for both start/end. "this week" = Mon-Sun. "this month" = first-last of month.
- Pass dates in search_by JSON. list_sessions_v2 uses overlap logic. list_readings_v2 filters on reading_date exactly.
</date_handling>

<multi_day_sessions>
Sessions span start_date through end_date (session_duration_days = end_date - start_date + 1). For per-day breakdowns, use list_readings_v2 with day_of_week filter. list_sessions_v2 date filters use overlap logic; list_readings_v2 filters on reading_date exactly.
</multi_day_sessions>

<local_timestamps>
All timestamps from tools are local clock time — display as-is, no conversion. tz_offset is reference only.
</local_timestamps>
